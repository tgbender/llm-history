# Codex rollout wire format

Reviewed 2026-11-07 against upstream revision `2bc8e7f5459b084afa482c7aac3f56fef36286b3`. Scope: durable rollout JSONL envelope, all 13 native `RolloutItem` variants and all 18 `ResponseItem` variants, selected nested payload declarations and custom codec transformations. [Machine-readable inventory](record-catalog.json) records exact variant names, accepted tags, source declarations and persistence caveats. Companion files cover event projection, storage and replay workflows.

## Historical unwrapped family

The explicitly inspected `rust-v0.20.0` snapshot (`45aed5edd139c38132de044596fdd55e47236657`) stores a distinct JSONL family: first an unwrapped `{id,timestamp,instructions,git?}` session header, then bare ResponseItem objects and optional `{record_type:"state",…}` state records. The state snapshot declaration is empty at that snapshot. These records have no modern outer type/payload envelope, line timestamp or ordinal. The header timestamp describes the session; retain item order without inventing per-item timestamps. [Historical declarations](https://github.com/openai/codex/blob/45aed5edd139c38132de044596fdd55e47236657/codex-rs/core/src/rollout.rs#L29-L55), [historical writer](https://github.com/openai/codex/blob/45aed5edd139c38132de044596fdd55e47236657/codex-rs/core/src/rollout.rs#L298-L339).

That historical resume reader parses the first physical line directly as SessionMeta, checks subsequent record_type=state objects before attempting ResponseItem, keeps its five recognized response variants, and skips malformed or Other items. The modern canonical envelope parser rejects these shapes, so select the format family before decoding. The current llm-history semantic decoder does not yet support this bare family; preserve its raw records and report that coverage gap. The catalog records three recognition/preservation cases and a format-family entry. A single observed release establishes existence at that snapshot; its introduction/removal dates remain unproven. [Historical reader](https://github.com/openai/codex/blob/45aed5edd139c38132de044596fdd55e47236657/codex-rs/core/src/rollout.rs#L158-L204), [modern envelope decoder](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/lib.rs#L45-L84).

## Modern envelope and codec

A modern enveloped stored line is a JSON object shaped as `{"timestamp":"…","ordinal":0,"type":"response_item","payload":{"type":"message",…},"metadata":{…}}`. `timestamp` is required text. `ordinal` is optional unsigned 64-bit integer; missing or null becomes absent. The outer item is flattened into the line, with snake-case `type` and a nested `payload`. Only `response_item` has the optional outer `metadata` sibling. `SessionMetaLine` flattens its metadata inside the payload, alongside optional `git`; it does not add a `meta` object. The writer timestamps each append in UTC with three fractional digits, serializes compact JSON, appends a newline, writes and flushes. Physical line order remains meaningful independently of timestamps. [Envelope](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/lib.rs#L391-L405), [writer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L2075-L2122).

The native `RolloutItem` has manual serde implementations through `RolloutItemWire`. The canonical reader parses JSON to `serde_json::Value`, removes and decodes timestamp/ordinal, then decodes the remaining object as `RolloutItem`. `RolloutLine` deliberately has no derived deserializer: the canonical path preserves nested decimal values across the flattened envelope. Keep raw bytes for faithful capture because typed reload intentionally normalizes or drops some fields. [Native codec](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/lib.rs#L237-L290), [canonical decoder](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/lib.rs#L45-L84).

These are disk objects. Responses API input/output uses some of the same `ResponseItem` declarations, but the rollout envelope, harness metadata and executive records are storage additions. `ResponseItemEnvelope` stores native item plus optional harness metadata; disk puts the item in `payload` and metadata beside it. A native envelope object with fields `item` and `metadata` is not the stored `response_item` payload. [Wire conversion](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/rollout_payload.rs#L34-L76).

## Content, media and asymmetric serde

Message content permits `input_text{text}`, `input_image` with flattened untagged image reference (`image_url` or `file_id`) and optional detail, `input_audio` with flattened audio reference (`audio_url` or `file_id`), and `output_text{text,annotations?,logprobs?}`. Image detail accepts auto/low/high/original. Provider annotations and logprobs preserve empty arrays. Inline URLs may hold data URLs; file references represent IDs, and retention must preserve their identity rather than pretending they are readable text. Untagged reference alternatives are tried in declaration order. [Content/media declarations](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L880-L975).

Tool `output` is a string or an array of `input_text`, `input_image`, `input_audio{audio_url}` and `encrypted_content` entries. Tool audio has its own narrower declaration; it has no `file_id` alternative. The native `FunctionCallOutputPayload{body,success}` custom serializer writes only body; reload resets success to None. Converting output-text message content to tool content drops annotations/logprobs. [Tool content and codec](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L2287-L2493).

Read/write symmetry varies materially:

- Reasoning `content:Some` is omitted when it contains no `ReasoningText`; content with a `ReasoningText` survives. `None` serializes null because the skip predicate returns false. [Predicate](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L1790-L1797).
- Passthrough `content_token_count` is read with default-on-error but skipped on write. `content_item_kinds` and `content_item_metadata` use default-on-error yet serialize when present. `cell_id`, `executed_tool_calls`, `tool_calls_complete` serialize when present but skip deserialization: a reloaded file cannot manufacture host execution proof. Decimal `create_time` uses `serde_json::Number`. [Passthrough](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L1002-L1051).
- Token usage's `codex_rollout_budget_units` is accepted but skipped on write. Cache-write input tokens default to zero. [TokenUsage](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/protocol.rs#L2520-L2544).
- Harness metadata renames native `history_truncation_token_limit` to `fallback_token_limit_override`. Most flags default false and omit false, while `client_authored` defaults false and still writes it. Empty Guardian vectors omit themselves. Invalid `mcp_attribution` becomes an AttributionError checkpoint. [Harness metadata and decoder](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/lib.rs#L67-L179).

## Compaction and retained evidence transforms

`CompactedItem` contains envelope-valued replacement history in memory. Wire replacement history contains bare `ResponseItem`s. If any replacement envelope has metadata, writer emits a positional `replacement_history_metadata` array of equal length, filling missing metadata with default objects. Reader rejects a metadata sidecar without history and rejects length mismatch. Legacy history without a sidecar produces envelopes without metadata. Keep sidecars aligned during filtering. [Compaction codec](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/rollout_payload.rs#L324-L468).

Compaction payload requires message; other checkpoint fields are optional. Most absent fields omit on write, but `compaction_response_id` and `latest_token_usage_record` serialize null. `window_id` accepts current string IDs or legacy unsigned window numbers; a legacy number fills absent `window_number`, then becomes no string window ID. Retained evidence, Guardian state, MCP resource origins, latest usage and resume metadata carry state needed beyond a summary's readable text. Converting `CompactedItem` to a plain response produces an assistant output-text message containing its summary and loses the checkpoint structure. [Compacted native type and summary conversion](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/lib.rs#L315-L389).

`RetainedContextEvent::DeliveredAssistantMessage` is written as `response_item/message`, role assistant, exactly one output-text item, phase absent, passthrough turn ID, metadata `user_input_order` and `delivered_assistant_message`. Complete marker is `codex:code-mode-delivery:v1:complete`; incomplete marker is `codex:code-mode-delivery:v1:incomplete:` followed by original bounded text. The incomplete message's visible text is the conservative unavailable-content placeholder. Reader recognizes this exact combination and reconstructs retained delivery evidence, with ordinary user origin, message ID string and absent phase. Marker mismatch or missing required recognition fields leaves an ordinary response envelope. Native retained delivery fields therefore do not all roundtrip unchanged. [Bidirectional transform](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/rollout_payload.rs#L171-L288).

Retained checkpoints contain ordered verified answers, original user messages, assistant messages, accepted file audio and sender deliveries. Ordered entries flatten their evidence beside revision, inherited flag and order. `incomplete` is the persisted name of verified-answer incompleteness; absent legacy user-message incompleteness defaults true. Accepted audio records carry turn/model/provider/file IDs. Verified answers carry original questions and answers. These fields establish provenance and ordering used by review/replay; text extraction should preserve their separate roles. [Retained declarations](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/retained_context.rs#L30-L215).

Turn-context writer flattens the profile-native context and appends legacy `sandbox_policy`, plus `file_system_sandbox_policy` when needed to describe differences. Reader prefers `permission_profile`; otherwise requires a legacy sandbox policy and converts split filesystem rules. Malformed historical split rules become restrictive empty rules. Legacy compatibility fields disappear from the native decoded context. [Writer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/rollout_payload.rs#L78-L134), [reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/protocol.rs#L3645-L3792).

## Acceptance, emission and reader failures

Enum acceptance is broader than ordinary writer output. All response variants except CompactionTrigger/Other pass the response persistence filter. Realtime records persist only in paginated mode. Events use a separate whitelist; legacy and paginated projection differ. Paginated ItemCompleted command output and MCP results can be truncated to 64 KiB by persistence policy. See the policy for the exact marker and full selection rules. [Authoritative persistence policy](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/policy.rs#L21-L291).

The canonical single-line parser returns errors for malformed JSON, non-object lines, missing timestamp, invalid ordinal, unknown outer tags and malformed typed payloads. Derived structs normally ignore unknown object fields; tagged enums need explicit `other` to accept unknown tags. ResponseItem and WebSearchAction have that fallback; ContentItem and outer RolloutItemWire do not. Unknown response payload fields are lost on typed serialization. Required field/type errors in a known variant remain errors.

The bulk resume loader skips whitespace-only lines, counts malformed JSON/typed lines and continues, and errors for entirely empty input. Before its first successfully decoded SessionMeta, it rejects an unknown history_mode as a file-level error. It chooses the first parsed SessionMeta's thread ID and retains later metadata records in the item list. It strips legacy ghost_snapshot response records and removes matching entries from compacted history with aligned sidecars. Malformed sidecar shape remains for typed rejection. Other readers may impose stronger consistency rules; this describes `load_rollout_items`. [Bulk loader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1128-L1195), [legacy stripping and mode guard](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1263-L1345).


## Nested checkpoint and permission inventory

The catalog's `nested_types` contains the exact source declarations, including type-level serde attributes, for 136 reachable payload and codec-helper types. `custom_codecs` contains source-linked implementations and field decoders. `audited_type_boundaries` explains library scalars, shared ownership containers, import aliases and the EventMsg/TurnItem handoff; `unresolved_type_references` is empty after this review. These inventories describe serde shape and normalization; arbitrary provider/plugin JSON remains explicitly open.

Guardian history has a third envelope shape: it serializes as an array of flattened response objects, with optional `guardian_metadata` inside each object. Reload wraps those objects back into `ResponseItemEnvelope`; older objects without guardian metadata remain valid. Guardian omission proof is an object with required `user_instructions` and `assistant_context` Booleans. A retained source is `{id:{message_id,turn_id,role},revision,complete}`; role is user/assistant and revision is an opaque ResponseItemId. Preserve the source revision and completeness separately from rendered text. Sender evidence stores receiver turn ID, receiver message ID and bounded text. The explicit `bound` method substitutes an omission message for text exceeding 3,600 bytes and truncates IDs to 128 bytes at UTF-8 boundaries; derived deserialization itself performs no bounding. [Guardian checkpoint codec](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/guardian_history.rs#L15-L57), [retained source identity](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/retained_source.rs#L15-L37), [sender evidence](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/history/src/sender_user_messages.rs#L6-L30).

Current permission profiles are tagged by `type`: managed carries `file_system` and `network`; disabled has no payload fields; external carries network. Managed filesystems are tagged restricted with entries and optional positive `glob_scan_max_depth`, or unrestricted. Network values are restricted/enabled. The decoder tries a tagged profile first, then a legacy untagged object with optional network/filesystem overlays; the legacy object rejects unknown fields. Missing legacy network becomes restricted; missing legacy filesystem becomes restricted with no entries. `ActivePermissionProfile{id,extends?}` preserves the selected profile's display identity beside its compiled permissions. [Profile declarations and conversion](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L305-L455), [legacy profile decoder](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L718-L805).

Filesystem entries cross the disk seam as raw entries: `path`, access read/write/deny, optional missing-path behavior skip. Read alias `none` normalizes to deny. Raw paths are tagged path, glob_pattern or special. Special paths use a separate `kind` discriminator: root, minimal, project_roots (alias current_working_directory), tmpdir, slash_tmp or explicit unknown carrying a path token and optional subpath. The explicit unknown representation preserves future tokens; an arbitrary unrecognized `kind` still encounters the derived enum's normal unknown-tag error. Raw filesystem policy adds kind restricted/unrestricted/external-sandbox, optional depth and default-empty entries. Literal native strings convert at an explicit seam to PathUri; conversion failures propagate through managed filesystem serde. The catalog preserves both raw and runtime declarations and their TryFrom implementations. [Raw permission types](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/permissions.rs#L119-L276), [path forms and conversion](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/permissions.rs#L434-L565).

The legacy overlay `FileSystemPermissions` has another custom codec: reader accepts canonical entries/depth or legacy read/write roots. Writer uses the legacy roots representation when the permissions can be projected into it, otherwise canonical raw entries. The canonical and legacy input objects reject unknown fields. This overlay is reachable from pre-tagged permission profiles; current managed profiles use their explicit tagged filesystem form. [Overlay codecs](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models.rs#L94-L250).

Dynamic tools use camelCase fields with `type:function` or `type:namespace`. Functions contain name, description, arbitrary JSON `inputSchema`, and default-false `deferLoading` omitted when false. Namespaces contain name, description and tagged function tools. SessionMeta's custom dynamic-tool field decoder accepts null/absent or a consistent canonical/legacy list. Legacy tools have optional namespace and exposeToContext; deferLoading wins when present, otherwise it becomes inverse exposeToContext, default false. Namespace members are grouped into namespace declarations. A list mixing legacy and canonical forms is rejected. DynamicToolsUpdated and compaction DynamicToolsSnapshot use typed vectors directly and therefore accept the canonical declarations through ordinary serde. [Tools and normalizer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/dynamic_tools.rs#L10-L175).

Selected capability roots carry stable `id` and location tagged `type:environment`, with `environmentId` and path. Path decode first accepts a PathUri, then converts a legacy native API path. PathUri's custom serde emits a URI string and parses it on read; AbsolutePathBuf serializes as a path and validates absoluteness on read unless a scoped deserialization base permits resolution. The catalog includes both implementations. [Capability codec](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/capabilities.rs#L10-L87), [path serde](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/utils/path-uri/src/lib.rs#L665-L695), [absolute path serde](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/utils/absolute-path/src/lib.rs#L396-L412).

MCP resource-origin checkpoints carry origins, ordered turn IDs and optional current turn ID. Each origin preserves call/turn identity, tool, connector, optional account link, URI and a default-false ambiguous-account flag. Attribution checkpoints carry status none/complete/attribution_error, optional error reason and default-empty sources. Attribution and source objects reject unknown fields. Error-reason decode ignores malformed values; unknown enum strings map to Unknown. The enclosing harness metadata decoder converts a malformed attribution object to an AttributionError checkpoint with empty sources. This double layer of normalization matters when preserving diagnostics from raw records. [MCP checkpoints and error decoding](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/mcp.rs#L67-L165).

Per-content metadata adds source attribution independently of message role. ContentItemKind is a transparent string. Namespace serde uses strings and preserves configured names through Other(String). Provenance is tagged unknown (read alias user_configured), developer_instructions, skills, agents_md, harness, tool or user. ContentItemMetadata's custom decoder prefers explicit provenance; otherwise legacy source_tool_namespace becomes tool provenance, harness_injected true becomes harness provenance, and other absent/false legacy values become unknown. Executed tool-call metadata and its truncation/result-source declarations are also inventoried even though the enclosing passthrough skips their deserialization. [Content attribution codec](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models/item_metadata.rs#L7-L115), [execution metadata](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/models/executed_tool_calls.rs).

Identity and settings types are inventoried through their leaves: ThreadId/SessionId use UUID string codecs; ResponseItemId accepts an opaque string; AgentPath uses a validated string conversion; GitSha is a string newtype; SanitizedGitUrl validates and removes credentials during its string conversion. SessionSource uses serde's externally tagged lowercase enum, so unit sources are strings while data variants are singleton objects; its Display text is a separate projection. ThreadSource uses string conversions and preserves unfamiliar feature names. Subagent provenance, history positions, context-window IDs, multi-agent version, collaboration settings, approval modes, reasoning settings and turn attribution are represented by their exact nested declarations in the catalog. ## Audited boundaries

EventMsg/TurnItem recursion is documented by the companion producer/lifecycle owner. Arbitrary JSON remains an intentional boundary for provider tools, tool-search arguments/results, tool input schemas, output annotations/logprobs, world state and reviewed actions. ## Saved-shape compatibility and preservation

Historical and present saved records belong in acquisition. The live writer rules above describe what that upstream writer emits. Preserve every captured record, its original type spelling, unknown fields and parse failures before applying typed normalization or the bulk resume loader's filtering. A historical alias's pinned-reader normalization describes how this checkout restores it; original release behavior requires the corresponding historical source snapshot.

The catalog's `compatibility_shapes` records recognition, reader, interpretation, preservation and pinned evidence for 30 compatibility cases. Release introduction/removal ranges remain unspecified where this review establishes only current acceptance or explicit compatibility code.
