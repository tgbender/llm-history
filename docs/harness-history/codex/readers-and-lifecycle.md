# Codex readers and conversation lifecycle

Review date: 2026-11-07. Upstream: `openai/codex`, revision `2bc8e7f5459b084afa482c7aac3f56fef36286b3`. This is a source-derived description of that revision. Upstream tests cited here were inspected, not executed. The operation inventory is [lifecycle-catalog.json](lifecycle-catalog.json). Related wire and producer catalogs are maintained separately.

The current-source inventories are a pinned baseline, not historical import allowlists. Additional historical tags, fields and producer behavior belong to separately pinned historical evidence; unknown saved records remain preservable input. The compatibility matrix below describes the current readers' observed treatment of older shapes.

## Three views of history

The durable rollout is an append log of records, including response envelopes, events, metadata, state baselines and compaction checkpoints. Model context is a reconstruction selected from that log and its referenced ancestors. Paginated API history is a SQLite projection of visible turns and items constrained by lineage. These are separate views with different occurrence counts and retention behavior. An importer should retain physical record identity and provenance before building either derived view.

A retained user message can appear as an original response, a checkpoint replacement-history element, and a copied child context item. Those appearances express context inheritance and snapshots. A fresh local child response/tool call and a local TokenUsageRecord represent new execution. Compaction snapshots and copied prefixes should not inflate execution or usage counts. The V2 inherited envelope marker and paginated child ordinal boundary are explicit evidence; legacy copies can lack precise per-item ancestry.

## Identity and family boundaries

`SessionMeta.session_id` identifies the root agent family/controller; normally it equals the root thread ID. `SessionMeta.id` identifies the logical conversation. `forked_from_id` is the immediate logical history source, and `parent_thread_id` identifies execution ownership. The physical rollout ID normally equals the logical thread ID but changes when a paginated thread is reverted. `history_base.thread_id` addresses a physical rollout, potentially an older ancestor generation. `forked_from_ordinal_exclusive` preserves the logical origin cutoff independently of a later replacement physical history base. See [protocol identity fields](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/protocol.rs#L3475-L3490) and [selected-rollout resolver](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_rollout_resolver.rs#L1-L30).

Session initialization chooses persisted resumed session ID, explicit host inherited session ID, then the non-root controller identity or root thread ID. A new ordinary user fork therefore creates a new family while retaining its fork origin. A forked subagent shares the parent's family/controller, receives a new logical ID, and normally records the immediate parent in both execution-parent and fork-origin fields. Nested children continue that family. [Identity assignments](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/session.rs#L1035-L1143), [child request assignments](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_manager.rs#L2250-L2272).

There are compatibility exceptions. Missing `session_id` deserializes as the record's own thread ID. Resuming a legacy non-root child whose synthesized session equals its own ID discards that value so controller inheritance can repair family identity. An isolated old export can therefore need external parent/controller evidence to recover its real family. Explicit `InheritedSessionId` is limited to a fresh directly host-started thread and must differ from its own logical ID. Ephemeral root forks can reuse source cache routing independently of lifecycle identity. [Legacy default](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/protocol/src/protocol.rs#L3609-L3615), [assignment and repair](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/session.rs#L1055-L1094), [host restriction](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_manager.rs#L2487-L2495).

Tests establish resumed root identity, restored child family identity, and protection against reading copied ancestor metadata as the child's own physical fork cutoff: [session tests](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/tests.rs#L7427-L7558).

## Fresh threads and resume

Persistent startup creates a thread-store writer/header and can defer the actual rollout file until persistence is needed. Initial model-visible context is deferred until the first real turn so turn-start overrides are applied once. Ephemeral startup omits thread persistence. A metadata-only reader can use the live writer's unpersisted metadata; for a live untouched thread without a saved metadata row it reports absence of a stored conversation without a filesystem scan. [Startup](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/session.rs#L1190-L1267), [metadata-only reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/read_thread.rs#L31-L65), [deferred-context test](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/tests.rs#L3214).

Resume acquires writer ownership and selects history/revision under that ownership, reconstructs context/runtime baselines and restores usage snapshots. It can append changed effective settings even if no new turn follows. Loaded historical content is replayed in memory and is not copied back into the existing log. Freshly forked history follows a different persistence branch. [Live resume](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/live_thread.rs#L182), [initial-history branches](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/mod.rs#L1750-L1900).

Reconstruction is more than concatenating response items. It chooses a surviving checkpoint, tracks active/completed/aborted turn boundaries, applies rollback to user-turn segments, restores previous turn settings and attribution, and replays world-state baselines. A legacy checkpoint without replacement history forces initial context rebuilding. Tests include rollback across incomplete compactions and reference-context reset/reestablishment: [reconstructor](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/rollout_reconstruction.rs#L250-L606), [reconstruction tests](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/rollout_reconstruction_tests.rs#L1169-L1442).

## User forks and exact cutoffs

Legacy user fork loads the source's full stored rollout, selects a snapshot and physically copies its retained prefix into a fresh thread. The child's canonical header comes first; later source metadata headers are historical copied records. Child effective settings are appended with the copied prefix so cold resume cannot mistake source settings for child settings. [Fork dispatch](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_manager.rs#L1745-L1807), [copied persistence](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/mod.rs#L1846-L1900).

Paginated user fork prepares a reference-backed snapshot. It reserves the source lifecycle, flushes/persists it, resolves physical lineage, materializes projection positions and produces a frozen `HistoryPosition` containing exclusive ordinal and decoded-byte offset. ThroughTurn requires a persisted completed turn; BeforeTurn requires a persisted start boundary. A selected inherited turn can point straight to an older physical ancestor. A zero-length selected segment collapses to its preceding ancestor boundary. Preparation requires the state DB. [Preparation and boundary selection](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/paginated_fork.rs#L18-L197).

The prepared model context is loaded for startup, but the child stores `history_base` and drains inherited items from its local append. Only its own settings and synthesized snapshot suffix are appended. The preparation reservation stays alive until the child's reference is durable, preventing a deletion gap. The test at [fork reservation](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history_materialization_tests.rs#L1425-L1459) demonstrates later parent writes do not alter the frozen prefix and a durable child reference protects the source.

Legacy `TruncateBeforeNthUserMessage(n)` uses a zero-based effective user-message boundary and cuts strictly before it. Out-of-range selection drops an unfinished turn, or retains the committed history if already at a boundary. `Interrupted` retains the persisted prefix and, when mid-turn, synthesizes an optional model-visible interruption marker and TurnAborted with source turn/root-turn attribution. Preserve these as child snapshot-boundary records. [Snapshot semantics](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_manager.rs#L218-L248), [synthesized suffix](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_manager.rs#L3150-L3233). User-index helpers apply rollback before counting boundaries and refuse unsupported synthetic legacy turn positions: [truncation helpers](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_rollout_truncation.rs#L35-L110).

## Subagents and forked subagents

Without fork mode, spawn creates fresh child conversation context while inheriting configured execution settings and family identity. With fork mode, it flushes parent persistence and reads legacy stored history or paginated latest model context. Both modes produce a physically copied child prefix, including when parent and child use paginated history. The spawn relationship is published before child storage creation. [Spawn dispatch](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/agent/control/spawn.rs#L734-L815), [parent load](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/agent/history.rs#L142-L266).

The default inherited-context filter retains system/developer/user messages and assistant partial/final answers. It excludes reasoning, ordinary tool call/output records, agent messages, communications, retained authorization, security scores and TokenUsageRecord. Some response forms, structural events and checkpoints survive. V2 `preserve_fork_prefix` with reusable baselines retains all response records, including tool history, and adds an explicit contextual identity notice. It marks inherited envelopes and strips sender/input-order provenance so old input cannot be recaptured as local authorization. Parent instruction fragments and usage hints are rewritten/removed according to version/config. These exact branch rules are in [history filtering](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/agent/history.rs#L47-L138) and [prefix processing](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/agent/history.rs#L279-L482).

Copied compaction checkpoints have parent usage record, guardian evidence and turn attribution stripped; replacement histories receive the same filtering. V2 retained context starts known-empty. The newest legacy checkpoint without replacement history invalidates reusable context baselines; a superseded older checkpoint does not. Under TokenBudget, copied child checkpoint windows are rewritten to a fresh child window numbered zero. [Checkpoint sanitization](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/agent/history.rs#L415-L456), [window rewrite](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/session.rs#L1100-L1112).

For paginated subagents, startup calculates the actual persisted prefix count, writes `subagent_history_start_ordinal = count + 1` in the header, then persists inherited model context. The later initial-history branch avoids a second copy. Projection consumes prefix records but emits no visible changes below this boundary. Thus model context can include parent user/tool material while API item history starts with the child's own occurrences. Missing response IDs are assigned before persistence. [Early durable prefix writer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/live_thread.rs#L152-L180), [projection suppression](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history_materialization.rs#L278-L285), [single-copy and identity test](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/agent/control_tests.rs#L2491-L2592), [projection test](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history_materialization_tests.rs#L1462).

## Compaction and long-running growth

Compaction replaces effective in-memory context and appends a checkpoint to the existing durable log. The implementation clones the replacement history into CompactedItem and appends Compacted, full WorldState, TurnContext and current settings. It also snapshots retained/guardian context, latest token usage and resume metadata. The writer opens the log in append mode. [Installation](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/mod.rs#L4864-L4926), [append-open](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1742-L1760), [pending-record writer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1870-L1922).

Consequently disk history grows across compactions even when model context shrinks. A checkpoint can repeat passthrough messages/instructions and state already present earlier. Older checkpoints remain. Legacy user forks multiply retained rollout history; forked subagents multiply reconstructed context/checkpoints; preserved-prefix children also copy tool history. Reference user forks share physical ancestors but require lineage/dependency management. Revert adds physical generations. Migration is an explicit rewriting exception described below.

Legacy full reader parses every nonempty line into a Vec; malformed lines are skipped, first metadata is canonical, and later copied metadata remains in the loaded record vector. [Full reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1129-L1190), [store call](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/read_thread.rs#L348-L357).

Paginated context reconstruction reverse-scans frozen physical segments newest first. It stops at the newest checkpoint with both replacement history and window number. Encountering a newer incomplete checkpoint forces full replay even past an older complete checkpoint. Requested canonical metadata is inserted once and ancestor headers are omitted from assembled model context. [Scan](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/model_context.rs#L186-L214), [stop rules](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/model_context.rs#L18-L48).

For plain JSONL this avoids parsing most old bytes. For compressed segments, opening a seekable reader fully decodes the entire physical file into an anonymous temporary file, then applies the cutoff/reverse scan. JSON parsing can be bounded while decompression I/O and temporary disk scale with the full opened segment, including an ancestor's bytes after the inherited boundary. Prefix validation separately uses zstd frame size or bounded decoding where possible. [Seekable reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/seekable_reader.rs#L68-L106), [prefix validation](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/seekable_reader.rs#L143-L165), [ancestor reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_lineage/ancestor_reads.rs#L62-L86).

## Rollback, revert and migration

Legacy rollback markers change effective user-turn visibility while retaining raw bytes. Reverse replay skips newest user-turn segments and surviving checkpoint state is selected consistently; simple physical suffix trimming fails for late events owned by older turns. [Reconstruction](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/session/rollout_reconstruction.rs#L303-L432), [migration ownership planner](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/rollback_plan.rs#L1-L102).

Paginated revert requires an unloaded thread and exclusive ownership. It creates a new immutable physical rollout whose SessionMeta.id remains the logical thread ID and whose history_base references the retained prefix. After persisting, it compare-and-swaps SQLite's selected path. Old files remain readable by existing children; failure of path CAS removes the new replacement file. Logical fork cutoff can shrink when reverting into inherited history. [Revert implementation](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/revert_thread.rs#L15-L153), [metadata preservation](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/revert_thread.rs#L180-L200), [tests](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/revert_thread_tests.rs).

Migration transforms legacy files into canonical paginated files and is not a raw-preservation operation. It locates canonical metadata even after a pre-header prefix, writes it at ordinal zero, resets history mode/base/boundary, drops subsequent metadata, assigns stable new ordinals, converts historical events and can synthesize modern turn/item completions. Narrow compatibility rewrites handle old collaboration settings, sandbox discriminators, string rate-limit timestamps, review prompt targets and command cwd paths. Retired guardian/name/undo events and ghost snapshots are skipped. ResponseItem::Other fails canonicalization. [Canonicalizer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/canonicalizer.rs#L1-L150), [compatibility parser](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/line_parser.rs).

The tolerant migration reader discards malformed or oversized records (16 MiB cap) and resynchronizes at newlines. On rollback it first builds ownership/replay metadata and then streams a second pass, removing markers and rolled-back content while rewriting retained checkpoints. The model-visible surviving conversation is the target, with raw source provenance lost unless separately captured. [Record reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration.rs#L1262-L1305), [two-pass writer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration.rs#L880-L1040), [rollback planner](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/rollback_plan.rs).

Legacy subagent migration prefers a bounded newest-checkpoint suffix, falling back to full tolerant replay. Its canonical output is marked entirely inherited through the end of migrated records. The bounded writer uses the canonical header timestamp for its selected items, so migrated timestamps can be synthesized rather than original event times. [Selector](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/subagent.rs), [bounded writer](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration.rs#L924-L965), [boundary publication](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration.rs#L770-L785).

Publication stages and syncs replacement bytes, verifies SQLite projection covers exact staged byte/ordinal end, checks source size/mtime to detect older writers, then renames replacement and finishes metadata. A durable pending journal coordinates crash recovery. Compressed input is staged decoded and output can be recompressed. Startup migration is conditional on feature plus state DB, uses a creation-order cursor/lookback and tracks skipped failures; busy files are retried. [Publication](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration.rs#L770-L875), [journal helpers](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/publish.rs), [startup](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_migration/startup.rs), [builder flags](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/core/src/thread_store_builder.rs#L59-L103).

## Lineage, archive and deletion ownership

RolloutLineage centralizes history_base traversal into ordered bounded ranges. It rejects cycles and invalid ownership/paths/offsets, includes archived ancestors and can retry another copy of the same physical rollout after failed ancestor reads. Newly shared standalone compressed history can be materialized for older-reader compatibility; already-shared ancestors remain read-only. History-page mode has additional visibility rules, including copied subagent prefixes and attached-fork synthetic abort boundaries. [Traversal and modes](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_lineage.rs#L23-L240), [fallback reads](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_lineage/ancestor_reads.rs), [cycle/offset/path/archive tests](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/rollout_lineage_tests.rs#L25-L542).

Archive locks lifecycle/writer ownership, rejects active writers and moves selected plus owned rollout generations into archive. It updates selected archived metadata and restores moves after failures. Unarchive moves owned generations back under dated active directories and returns metadata-only root. Caller-supplied descendants are handled best effort after the parent succeeds. These are ownership-preserving moves, so references can resolve archived ancestors. [Archive](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/archive_thread.rs#L14-L149), [unarchive](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/unarchive_thread.rs#L20-L145).

Hard delete rejects attached children and external physical references. A batch subtracts references internal to its own physical deletion set. Host cleanup runs under ownership before file removal; main state rows are removed only after every associated rollout is removed, preserving retry information. A missing discovered file counts as already deleted. Archive/delete reference scans and retained generations add cost as saved rollout population grows. [Deletion and reference counting](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/delete_thread.rs#L1-L213), [reference index](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/rollout_reference_index.rs).

## Turn-item projection schemas

The JSON catalog contains all 19 core `TurnItem` variants and all 19 public `ThreadItemPayload` variants, their exact field types/serde attributes, projection mappings, and a recursively linked named-type registry. Core uses a `type` tag with Rust variant names; public payload tags and variant fields use camelCase. `ThreadItem` flattens the payload and adds lifecycle milliseconds, normalizing legacy completion timestamp zero to absence.

Projection can change information: agent Text fragments concatenate into text; command vectors/parsed actions become presentation strings/actions and empty command output becomes null; durations become checked milliseconds; path URIs become legacy API path text; review structures become formatted text; missing file status becomes inProgress; hosted image result becomes inline GeneratedImageRef while extension image items keep their richer typed shape. Core Extension dispatches to public imageGeneration, sleep or webSearch. Hook fragment metadata and command analytics-only fields are skipped from serde. These transformations mean API payload equality cannot establish raw record equality. [Conversion](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L954-L1160), [wrapper](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L251-L300), [schema tests](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/app-server-protocol/src/protocol/v2/tests.rs#L3175-L3730).

## Reader inventory and corruption behavior

Path selection is centralized: live writer, SQLite selected rollout, filesystem fallback, then optional archive fallback. For a SQLite-identified paginated thread, its selected path is authoritative; fallback must not accidentally resurrect an old revert generation. [Resolver](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_rollout_resolver.rs#L67-L145).

Readers differ intentionally:

| Reader | Input and output | Important boundary |
| --- | --- | --- |
| Metadata/read_thread | live metadata, SQLite and rollout header/display fields | Metadata-only read can avoid full file load; paginated display state comes from SQLite |
| Legacy include_history | full decoded rollout → record vector | First metadata canonical; malformed lines skipped |
| Latest model context / prepared fork | reverse physical lineage → checkpoint plus suffix | Complete checkpoint required for bounded replay |
| Paginated list turns/items/timeline | projected SQLite rows constrained by lineage | API items are derived visibility, with page/cursor/mode validation |
| Search occurrences | projected user/assistant item candidates | Scoped search/cursor; bounded lineage; not every raw response payload |
| Original history tail/After | fixed complete root raw suffix | Root-only, contiguous ordinals; rejects forks, subagents and reverted physical IDs |
| Migration readers | tolerant legacy compatibility replay | Can drop/rewrite historical source and synthesize events |
| Header/item helper readers | prefix/header or selected item | Neither a full physical inventory nor a universal model replay |

Sources: [read_thread](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/read_thread.rs), [metadata helpers](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/metadata.rs), [paginated reads](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history/read.rs), [timeline](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history/realtime.rs), [search](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history/search.rs), [original-history reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/original_history.rs#L33-L115).

Projection advances in bounded batches/short transactions and commits byte/ordinal checkpoints. It ignores an incomplete final newline record until completed. Malformed JSON, unknown records, missing ordinals and duplicate/regressed ordinals are skipped with anomalies; unknown records advance byte position but leave ordinal choice to the next decodable line. This allows a later known record to resolve reuse versus a gap. Copied inherited subagent records advance checkpoints without local changes. Preserve raw unknown records in an importer instead of copying this lossy projection policy. [Materialization](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history_materialization.rs#L180-L285), [batch pipeline](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/thread_history_materialization_pipeline.rs#L1-L105).

Legacy full-load behavior differs: it loops text lines and attempts JSON/decode, skips malformed records and ghost snapshots, and rejects an unknown canonical history mode. It can attempt a final non-newline text line, whereas projection and original-suffix acquisition use complete-record boundaries. Reverse scanners expose rejected outcomes and model-context callers skip them. Error tolerance therefore belongs to each reader, not a universal file-validity flag. [Legacy decoder](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1129-L1190), [unknown mode](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1265), [model scanner caller](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/thread-store/src/local/model_context.rs#L186-L214).

Plain/compressed sibling discovery selects one physical representation; seekable readers retain open file handles or anonymous decoded snapshots across concurrent compression. Append materializes compressed bytes before reopening the plain log. Frozen bounds always address decoded JSONL bytes. An importer should preserve the logical physical-rollout identity across representation changes and exclude temporary staging/journal files from conversation occurrence counts. [Representation reader](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/seekable_reader.rs#L1-L106), [append reopening](https://github.com/openai/codex/blob/2bc8e7f5459b084afa482c7aac3f56fef36286b3/codex-rs/rollout/src/recorder.rs#L1742-L1760).

## Explicit historical reader: unwrapped saved sessions

The separately pinned v0.20.0 snapshot (`45aed5edd139c38132de044596fdd55e47236657`) has its own saved dialect and resume reader. Its first line is unwrapped SessionMeta with optional flattened git; subsequent lines are bare ResponseItem or `record_type: "state"` snapshots. Per-record modern timestamps and ordinals are absent. Resume reads the whole text, requires a decodable first header, skips malformed later JSON, updates the latest decodable state snapshot, collects recognized responses and ignores Other. [Historical reader](https://github.com/openai/codex/blob/45aed5edd139c38132de044596fdd55e47236657/codex-rs/core/src/rollout.rs#L158-L210), [historical writer](https://github.com/openai/codex/blob/45aed5edd139c38132de044596fdd55e47236657/codex-rs/core/src/rollout.rs#L293-L325).

The modern canonical decoder requires a timestamp and modern item envelope. Its rejection of this saved dialect establishes a decoder mismatch. The current migration compatibility parser also targets enveloped records. Import must recognize and route the unwrapped dialect separately, preserve first header/git and each state/response occurrence, and retain absent timestamps/ordinals. The historical catalog owns the wider snapshot comparison; this entry establishes the actual reader path for this concrete saved shape.

## Hosted / CCA boundary and explicit gaps

This public revision's configured builder selects Local or InMemory ThreadStore. Core and app-server operate through the ThreadStore abstraction. The non-local regression suite uses InMemory and checks that no local rollout/SQLite artifacts are produced. CCA strings in originator selection identify service provenance; they do not specify remote physical persistence. A source comment mentioning CCA metadata ordering is insufficient to establish its backend storage. Shared InitialHistory/reconstruction APIs can carry common semantic objects across backends; remote storage files, database layout, durability guarantees and server-side compaction remain unestablished here. The catalog records the backend boundary explicitly.

Coverage limits: this document traces local conversation lifecycle/readers and migration, rather than every adjacent host-owned artifact or every API projection field. 2. Root user/tool/usage → ordinary filtered child and V2 preserved-prefix child → grandchildren. Verify root family stays shared, immediate parent linkage changes, child usage starts locally, and inherited tool handles are historical.
3. Two turns → complete compaction → fork → revert root before second turn → resume root and child. Verify stable logical ID, new selected physical generation, old child dependency, checkpoint snapshot counts and archive resolution.
4. Newer incomplete checkpoint after an older complete checkpoint. Verify full replay is required. Repeat with compressed ancestors and distinguish parsed suffix size from decompression size.
5. Crash after paginated child header and part of copied prefix. Verify inherited boundary suppresses prefix from presentation; resume/writer ordinal rules preserve child-local start.
6. Legacy rollback with a late completion for an older surviving turn, plus a checkpoint containing removed input. Migrate and compare effective model context; verify obsolete markers/content omitted and original raw acquisition retained separately.
7. Malformed complete record, unknown tag, duplicate ordinal and partial final line. Compare raw preservation, legacy full load, projection, original suffix and migration results.
8. Archive multi-generation root with referenced child; unarchive; attempt delete root alone and then internal batch. Verify ownership moves, dependency protection and retry graph behavior.
