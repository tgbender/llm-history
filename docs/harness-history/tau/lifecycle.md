# Tau lifecycle, replay and capture

## Discovery, indexes and archives

Default application home is `~/.tau`; `TAU_HOME` overrides it and must expand to an absolute path. Sessions live under `<TauHome>/sessions/`. A project directory name uses a normalized cwd slug (up to 72 characters) plus `-` and the first six hex characters of SHA-256 of the resolved cwd. Home-relative slugs begin with `home`. Normal new transcript filenames are `<session-id>.jsonl`, default IDs UUIDv4 hex; the project default session uses `default.jsonl` and index ID `default-<project-directory-name>`. [Path definitions](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/paths.py#L12-L44), [slug/hash](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/paths.py#L139-L179), [ID/path creation](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L330-L397).

Discovery is **index driven**. Each project has `index.jsonl`; a legacy global `sessions/index.jsonl` is also read. `sessions/archive.jsonl` holds archived metadata. Normal list reads project/global indexes, deduplicates by `id` retaining greatest `updated_at` (later record wins equality), and sorts newest updated first; cwd filters compare resolved paths. A supplied cwd is a lookup hint before all indexes. The manager does not reconstruct missing index rows by scanning every transcript body. Capture orphan/unindexed transcript files in addition to index-discovered files when completeness matters. [List/get/archive](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L145-L262), [index scans](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L436-L478), [deduplication](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L528-L534).

An index line is a `SessionRecordModel` JSON object with **snake_case** fields:

| Literal field | Meaning/default |
| --- | --- |
| `id` | Required session ID |
| `path` | Required transcript path string; used for resume |
| `cwd` | Required project cwd path string |
| `model` | Required selected model string |
| `provider_name` | Optional string, default None |
| `inference_provider` | Optional string, default None |
| `inference_provider_mode` | Optional `automatic` or `fixed`; missing/None is interpreted as fixed when inference_provider exists, otherwise automatic |
| `title` | Optional string, default None |
| `created_at`, `updated_at` | Required numeric Unix seconds |

The index model uses `extra="ignore"`, unlike strict transcript entries. Rewriting an index can drop unknown index keys. `model_dump_json()` for index rows includes None as JSON null and normal defaults. Index writes rewrite the file; they do not use the transcript's lock/temp/fsync transaction implementation. Index metadata may lag a successfully committed transcript. Title changes update index rows; current `set_session_name` does not append a session_info title change. Keep index title separately from any historical session_info.title. [Index model](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L56-L120), [index write](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L480-L492), [title writer](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L2878-L2924).

Archive moves metadata from active index(es) to archive.jsonl while preserving the transcript at its path; unarchive reverses metadata visibility. Archive is therefore not transcript deletion or a filesystem move. A failed exclusive session reservation/index operation can remove its newly created empty transcript as rollback; that is distinct from archive. The reviewed manager exposes no ordinary content-pruning/entry-deletion API. [Archive implementation](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L198-L262), [exclusive reservation rollback](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_manager.py#L289-L328).

## Physical order, tree and current branch

Storage order is JSONL line order. Entry timestamps are independent metadata; do not use them to recover order. Parent ancestry selects the active branch. The generic tree helper rejects duplicate IDs, missing parents and cycles in traversed paths. CodingSession.load first detaches references to missing parents in its in-memory copies, permitting an imported/extracted branch to become a root. The original file's dangling pointer remains original evidence. [Tree validation](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/tree.py#L12-L40), [load detachment](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L509-L530), [detacher](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L4267-L4275).

`SessionState.from_entries()` by default selects the **last non-leaf record in file order**, including custom state, labels or model changes. Legacy `leaf` entries are readable but never select active tip. Explicit `leaf_id=None` selects the empty path; explicit ID traverses root-to-leaf. When the selected history needs no tool-history repair, ordinary tree navigation changes memory only. Next append records the chosen parent; reopening before an append returns to file-order tip. Navigation can append a repair branch immediately when tool history needs repair, as described below. Selecting a user-message node without summary branches before that user and prefills its text; other branchable entries are selected at their node. When there are abandoned messages to summarize, a requested branch summary appends at the destination and durably becomes tip. [State default and replay](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/memory.py#L38-L125), [navigation](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L1033-L1107).

Labels are resolved **globally** in physical order, including off-path labels; trim value, set on nonempty string, clear on None/empty. Target ID and parent ID have different meanings. Model, provider, thinking level, session_info and custom entries replay on the selected ancestry only. An old model_change omitting provider preserves the previous branch provider. Session-info state is last on-path entry. The TUI tree presentation orders sibling branches by longest retained history, stable for equal lengths; that layout is a derived view. [Replay/settings/labels](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/memory.py#L69-L148), [tree layout](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L4336-L4407).

## Compaction and effective context

SessionState retains the active ancestry as `entries`, while `messages`/`context_entry_ids` describe its context-producing projection. Ordinary message entries append nested messages. Top-level custom_message synthesizes a runtime custom message; custom state adds no message. Branch_summary adds a user message with a summary wrapper. Labels, legacy leaves and selection state add no messages. [State construction](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/memory.py#L69-L125).

Compaction produces `UserMessage("Previous conversation summary:\n" + summary)` and replaces older context:

- If the input explicitly supplied `replaces_entry_ids`, that legacy ID set takes precedence over first_kept_entry_id. Replaced rows are removed; summary is inserted at the first removed row, or appended when none matched. Explicit `[]` keeps all prior rows and appends summary.
- Otherwise resolve `first_kept_entry_id` against the **whole preceding active path**, including state-only records. Keep existing message contributions at/after that inclusive boundary, in path order, and prepend summary. Missing/null/nonmatching boundary retains only summary. Earlier retained compaction contributions follow the existing rows as implemented; replay proceeds sequentially through compactions.

Original summarized messages and abandoned branches remain physically stored. The `tokens_before`, usage and provider/model fields describe summary generation/context accounting; they do not define another ordering relation. [Exact compaction logic](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/memory.py#L151-L207), [boundary tests](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/tests/test_session.py#L641-L857).

Provider-safe context can differ further: coding-specific messages are transformed for provider use, system prompt/resources are separately assembled, and tool history can be repaired. A rendered display, provider request, active SessionState.messages, and complete native file each have different retention scope. Preserve native storage first, then compute explicit derived views.

## Persistence, failure and durable repairs

`JsonlSessionStorage` uses adjacent hidden `.<filename>.lock` and `.<filename>.tmp` files. Single append locks exclusively, removes incomplete temp, appends UTF-8 bytes, flushes and fsyncs. `append_batch` creates the complete prior-bytes-plus-batch file in the same directory, fsyncs, replaces the transcript and fsyncs directory where supported; it is the startup/model-switch/repair transaction boundary. Read uses shared lock where available and returns isolated deep copies; Windows uses exclusive locks. Incomplete temp is discarded as uncommitted. The parsed cache tracks `(mtime_ns,size,inode)` and re-reads on external changes. [Storage protocol](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/storage.py#L24-L134), [atomic replace and locks](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/storage.py#L159-L228), [lock implementations](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/storage.py#L260-L298).

Empty-session load stages session_info → model_change → thinking_level_change linked entries. Authoritative initialization can be deferred until use; indexes and physical file creation are separate steps. Completed `MessageEndEvent` is the message persistence boundary; streaming deltas are not individual native entries. Persistence retries keep a stable prepared entry ID, check durable IDs and avoid repeating an append that already reached disk. Custom runtime messages become custom_message entries. [Startup](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L509-L530), [message persistence](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L3640-L3684), [initialization](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L3759-L3843).

On load/branch, malformed active tool history can produce a durable **repair branch** rather than rewriting original messages. Tool repair places exactly one result adjacent to each call occurrence, synthesizes missing interruption results (`isError=true`), drops orphan/duplicate results and reorders misplaced results, preferring real results over synthetic interruption placeholders. Matching accounts for repeated call IDs by occurrence and existing adjacency. The coding writer finds a common prefix, appends a custom diagnostic with namespace `tau.session-history-repair` and `data.version=1` plus counters `synthesizedResults`, `droppedOrphanResults`, `droppedDuplicateResults`, `reorderedResults`, appends repaired suffix messages, restores model/thinking state and copies applicable custom state with fresh IDs. The original branch stays in the file. [Repair algorithm](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/tool_history.py#L19-L165), [durable branch writer](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L3570-L3638), [repair prefix selection](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L5251-L5276).

## Codec migrations, imports and exports

The codec applies targeted legacy migrations before strict validation, without a header version gate:

- Target-less legacy label gets the earliest `message`/`compaction`/`branch_summary` ID in the complete file; fallback is earliest non-label/non-leaf ID. Single-line parsing falls back to that label's parent or own ID.
- Top-level custom_message `customType` becomes `custom_type`; canonical snake_case wins when both are present.
- Legacy user message with custom_type/customType becomes custom, then migrates to top-level custom_message; nested custom timestamp milliseconds becomes outer seconds.
- Legacy assistant string content plus tool_calls/toolCalls becomes ordered text/call blocks. Null usage.cost becomes `{}` for default cost population.
- Legacy `role: tool` becomes toolResult; `name`→toolName, `tool_call_id`→toolCallId, `ok`→inverted isError. String content becomes text blocks; data/details merge (details wins conflicts), and error text fills empty content.

The codec decodes a copy; storage read does not rewrite earlier lines to canonical form. Blank lines are skipped; malformed JSON/validation errors abort with line numbers. Unlike Pi's loader, Tau does not skip malformed nonblank lines or add a newline repair on read. [Full migrations](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_agent/session/jsonl.py#L35-L171).

Explicit storage paths and in-memory missing-parent detachment allow existing/extracted histories to be loaded, but this is not a blanket promise of Pi-file compatibility: a Pi header and camelCase outer parentId fail the Tau entry schema. No arbitrary multi-harness importer was identified in the reviewed modules. JSONL export serializes all supplied entries; CodingSession.export supplies the complete read entry list, including off-path branches. HTML export embeds a downloadable JSONL body and receives current system_prompt separately for display. Export's null/default emission differs from canonical storage as described in [format](format.md). [Export call](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session.py#L1159-L1184), [serializer](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_export.py#L74-L84), [embedded download](https://github.com/huggingface/tau/blob/47610d3ed71deb70b07443a8641588ffc9c8ffc6/src/tau_coding/session_export.py#L177-L204).

## Capture and content-addressed extraction

The following capture/importer recommendations are inferred from the native behavior above; they describe archival design choices for consumers.

Capture transcript bytes plus project/global/archive indexes, preserving each native path and producer. Indexes contain the session ID, current title, timestamps, routing choices and archive membership that cannot be inferred exactly from transcript alone. Conversely transcripts can outlive missing index rows. Capture both; scope entry identity to source/session and physical occurrence, preserving repeats caused by repair branches. For concurrent sessions take a consistent snapshot or record/retry changed files; do not merge index and transcript timestamps into one clock.

Reusable CAS bodies include exact text/thinking strings, image bytes + MIME type, ordered content arrays, tool arguments/results, summary text, and custom JSON bodies. Native occurrence metadata includes source/session identity, line coordinates/order, IDs/parents, outer seconds timestamps, nested millisecond timestamps, roles, model/provider/routing, usage/timing, signatures, diagnostics, labels, branch boundaries and raw field presence. Keep these independently queryable and retain original structured bodies. Plain-text extraction alone loses images, call pairing, block order and provider replay data.

Lossless reconstruction requires raw bytes (JSON key order, escaped spelling, number spelling, newline state), plus metadata for omitted/default/null fields. In particular, a normalized Pydantic object loses legacy syntax, unknown fields rejected by this release, and the explicit-empty compaction-set distinction after standard serialization. Preserve raw data and codec revision before deriving normalized views.

Capture referenced full-output files (`fullOutputPath`) and any custom/details attachments separately when available; a string path is only a reference. Tau's runtime system prompt, loaded context files, skills, prompt templates, tool definitions/extension code, settings and provider adapters are external context dependencies. Native transcript AgentMessage has no system role here; transcript alone cannot recover the exact system prompt used on every past request. HTML export's separately supplied current prompt is a snapshot of export-time state. Compaction summaries and repaired tool results contain generated/synthetic content; retain provenance as native record type/namespace rather than treating every message body as original provider output.
