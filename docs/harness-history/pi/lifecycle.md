# Pi lifecycle, replay and capture

## Discovery and filesystem layout

Default agent root is `~/.pi/agent`; `PI_CODING_AGENT_DIR` overrides it. Default session files live under `sessions/<encoded-cwd>/`: resolve cwd, remove its leading slash/backslash, replace slash/backslash/colon with `-`, wrap in `--`. New filename is `<ISO timestamp with colons/dots replaced by hyphens>_<session-id>.jsonl`. Explicit session files, SDK session directories, `--session-dir`, and CLI `PI_CODING_AGENT_SESSION_DIR` can place files elsewhere. Capture configured roots as well as conventional roots. [Agent root](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/config.ts#L602-L635), [directory/filename](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L586-L603), [CLI override](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/main.ts#L747-L758).

There is no separate persistent index in this SessionManager. Per-project listing scans JSONL files; all-project listing scans child directories under the sessions root. Exact-ID discovery reads headers. Header discovery skips blank/malformed lines, stops if first parsed entry is not a header, and caps synchronous header scans at 1 MiB. Explicit open falls back to full loading for an oversized otherwise compatible header. Most-recent continuation sorts valid candidate files by filesystem `mtimeMs`; listing's activity time instead uses latest user/assistant nested timestamp (outer timestamp fallback), then header time or file mtime. Listing counts all physical `message` entries and searches user/assistant text across all branches. Its count and text are summaries of retained storage. [Header reader](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L605-L740), [recent](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L749-L768), [listing summary](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L800-L881), [all directories](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1933-L2008).

## Ordering and active branch

1. Retain physical line order, including state-only entries. The header is excluded from the tree index.
2. On reopen, the last non-header entry in physical order becomes active leaf. There is no durable independent selected-leaf property.
3. Walk `parentId` to root and reverse to obtain chronological ancestry. A `null` requested leaf means the empty path; a missing explicit leaf in the standalone path builder falls back to the last entry. The manager's `branch()` checks target existence.
4. Branch navigation alone changes the in-memory leaf. A subsequent append records the new branch parent and makes that branch durable. Reopening before any append selects the previous last stored entry.
5. UI tree children are sorted by entry timestamp; that presentation sorting differs from physical order and ancestor order.

Duplicate IDs overwrite in the JavaScript index; orphan parents stop ancestry traversal and UI `getTree()` exposes orphans as roots. The ancestry loop lacks cycle rejection. A capture/parser should retain raw anomalies and report invalid topology rather than silently reproducing an infinite traversal. [Index/default leaf](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1104-L1123), [path builder](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L381-L416), [navigation](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1584-L1635), [UI tree](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1535-L1577).

Labels are resolved over **all** file entries in file order, including off-path changes. Latest truthy label sets the bookmark; empty/omitted label clears it. Latest file-global `session_info` controls the name, including an explicit clear. These records can still be in the tree ancestry and advance the persisted tip. Model/thinking settings are branch-local: default `thinkingLevel` is `off`, default model null; latest model_change or assistant message sets model. [Global labels](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1104-L1123), [global name](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1314-L1339), [context settings](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L418-L433).

## Effective context

Take the selected full ancestry first. Find its latest compaction. With no compaction, retain the full path. With one, context entries are: the latest compaction, the inclusive retained range from `firstKeptEntryId` to just before compaction (excluding old system messages), then entries after compaction. A boundary equal to the compaction's own ID retains none of the earlier range. Missing boundary similarly contributes no prior entries. Earlier compaction records inside a kept range remain native records but do not add an extra summary/checkpoint in the projection. [Context selection/projection](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L468-L573).

Scan the resulting context entries for `context_edit` and keep the latest edit per target. Then project each entry: ordinary message contributes its message; custom_message contributes a runtime custom role; latest compaction contributes its system checkpoint when present plus a runtime compaction summary; nonempty branch_summary contributes a branch summary role; state entries contribute none. Apply omission/content replacement to the target contribution. Edits outside the active context range have no effect. Retain both raw entries and this derived view so an edited message's original usage and original body remain attributable. [Projection](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L439-L584).

`convertToLlm` subsequently changes coding-specific roles: custom becomes user; summary roles become user text with wrappers; bashExecution becomes user text unless `excludeFromContext` is true. Core system/user/assistant/toolResult pass through to provider conversion. Provider-specific adapters can alter replay further, including translating signatures and system/tool state. Native JSONL therefore captures a richer history than a provider request or display transcript. [Runtime-to-LLM conversion](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/messages.ts#L140-L196).

## Persistence and mutations

The coding-session event listener persists completed `message_end` messages: system/user/assistant/toolResult become ordinary message entries, while runtime custom messages become top-level custom_message entries. Bash execution and summary records use their dedicated paths. Streaming partial/delta events are runtime events; the stored record captures the finalized message. [Event persistence](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/agent-session.ts#L1211-L1233).

New header/setup entries remain in memory until the first user or assistant message. Then the writer uses exclusive creation (`wx`) and writes all pending entries. Further appends serialize one object plus newline. Append failure rolls back its in-memory entry/index/leaf. There is no fsync/locking transaction protocol in this writer; capture a stable file snapshot or retry on concurrent change. An explicit empty existing session file is initialized immediately with a valid header. [Open](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1030-L1055), [persistence](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1161-L1206).

Compaction and context editing append records; summarized and edited bodies remain in the source file. Branch-with-summary appends at the destination with `fromId` referencing the abandoned tip. Ordinary entry modification/deletion is outside the manager API. The interactive session picker deletes a **whole file**, first through the `trash` command and then permanent unlink if necessary. No archive sidecar is declared by the reviewed SessionManager; an external backup/trash system may retain deleted files. [Branching](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1584-L1635), [delete](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/modes/interactive/components/session-selector.ts#L642-L678).

`createBranchedSession(leafId)` creates a new session header/ID with `parentSession` path, copies only the requested ancestry, removes old label records, rechains retained entries, adjusts compaction boundaries that pointed at removed labels, then appends regenerated current labels for retained target IDs using original label timestamps. Retained entry IDs survive. `forkFrom` creates a new header/session ID/cwd and copies **all** non-header records, including abandoned branches, unchanged; opening the copy may then migrate it. Both operations can create repeated native entry IDs in distinct sessions. [Path extraction](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1638-L1759), [full fork](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1819-L1881).

JSONL export serializes the current branch only, rechains parent IDs starting at null, keeps session ID, and creates a new header timestamp/cwd without parentSession. Optional export-only trailing entries may be supplied by share/bug-report callers. Export omits off-branch records and off-branch label changes; it is not an exact raw-file backup. HTML exports are presentation artifacts. [Exporter](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-export.ts#L8-L45).

## Load repair and migration

The loader skips blank lines and JSON syntax errors, preserves parsed objects without strict schema validation, and requires the first parsed record to be `session` with string id. A valid session with an unterminated final fragment gets a newline appended even when that fragment was malformed, preventing a later append from joining it. Nonempty invalid sessions cause explicit open to fail without replacement. For archival capture, read bytes directly rather than opening through this mutating loader. [Reader repair](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L617-L670), [invalid-file handling](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1030-L1047).

Absent header version means v1. v1→v2 assigns fresh IDs, links entries linearly through parentId, converts compaction `firstKeptEntryIndex` into `firstKeptEntryId`, and removes the old index field. v2→v3 renames nested `message.role: hookMessage` to `custom`. Manager load rewrites the file when migration runs. Versions at least 3 bypass these migrations. Exact original IDs/formatting and invalid lines cannot be recovered from a migrated rewrite. Preserve original bytes before normalization. [Migrations](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L286-L351), [rewrite on load](https://github.com/badlogic/pi-mono/blob/a4ccccbd64d4ccea1644f5a07bb94ef09075b219/packages/coding-agent/src/core/session-manager.ts#L1086-L1135).

## Capture and content-addressed extraction

The following capture/importer recommendations are inferred from the native behavior above; they describe archival design choices for consumers.

Capture the full JSONL byte stream, source identity, relative path/discovery root, observation time and physical line/byte coordinates. Preserve all branches, metadata, unknown fields and malformed lines. Keep source file identity separate from header session ID: copies/exports can reuse session IDs and forks reuse entry IDs. Record file stat evidence when useful for detecting concurrent append/rewrite. The selected in-memory leaf before an append is unavailable from disk.

Reusable CAS bodies can include exact text strings, thinking text, image bytes with MIME type, ordered structured content arrays, tool arguments, tool outputs, summaries and system prompt sections/tool schemas. Keep occurrence/native metadata separately: source/session identity, entry IDs/parents/order, both time layers, role, signatures, response IDs, model/provider, usage, errors, branch boundaries, edits, labels and extension fields. Preserve the whole structured block alongside extracted searchable text; joining prose drops block order and signatures. Reconstructing exact bytes requires original line bytes or a lossless raw representation because key order, escaping, omitted values and number spelling are otherwise normalized.

The source file embeds image bodies, but `bashExecution.fullOutputPath` and tool/custom details can reference external files. A copied path string does not capture the referenced bytes. Preserve available dependencies separately with an explicit reference map. The transcript records system/tool deltas and compaction checkpoints in this revision; older files can lack them. Extension code, tool implementations, provider adapters, settings, skills and files read by tools are additional dependencies for recreating execution. A summary preserves its generated text and boundary, while the source tree preserves the original messages until whole-file deletion; the summary alone cannot regenerate them.
